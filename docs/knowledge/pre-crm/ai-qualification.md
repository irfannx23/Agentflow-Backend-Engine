# AgentFlow signup ICP qualification

The canonical implementation is generated by
`builders/build_lead_qualification_workflow.py` from the code-node modules in
`core/pre-crm/n8n-code-nodes/`. The committed workflow JSON is generated output,
not an independent source of truth.

## Purpose

Signup qualification measures organization/ICP fit from verified, normalized
firmographics. It does not infer buying intent. AgentFlow product behavior is
evaluated later by the RevOps/PQL system.

The initial pipeline is:

`user.registered → email verification → Apollo organization enrichment → normalized firmographics → Gemini ICP scoring → qualification/routing`

No additional signup questionnaire and no Clay dependency are required.

## Normalized inputs

Only fields present in Apollo or the actual signup context are retained:

- company name and domain
- industry/industries
- employee count
- country, region, and city
- factual organization description and founded year
- total funding, latest funding stage/date, and headcount growth when returned
- technologies only when Apollo explicitly returns them
- email-verification state and business/personal classification
- acquisition source, auth provider, and signup event context

Arbitrary inbound `monthly_spend`, `budget`, `pain_points`, and `tech_stack`
fields are not copied into the scoring object. Missing values remain missing.
The raw Apollo response is not sent to Gemini.

## Gemini contract

Gemini receives the normalized object and must return only JSON:

```json
{
  "icp_score": 82,
  "fit": "high",
  "buying_intent": "unknown",
  "qualification_reason": "The company has meaningful operational scale and explicitly documented integration tooling.",
  "company_summary": "A B2B software organization with 420 employees.",
  "personalized_icebreaker": "Your integration footprint suggests meaningful workflow complexity. AgentFlow may help orchestrate those processes."
}
```

`icp_score` is an integer from 0–100. `fit` is `high`, `medium`, or `low`.
At signup, `buying_intent` must be `unknown`. The parser rejects inferred
`high`/`medium`/`low` intent, malformed JSON, safety blocks, missing candidates,
missing text, invalid fit, and out-of-range scores.

The workflow persists database buying intent as `NULL`, the existing database
representation of unknown, while preserving the explicit `"unknown"` value and
the full qualification explanation inside the firmographic qualification audit
object.

## No-match and failure behavior

When Apollo returns no organization, Gemini is not asked to invent one. The
workflow records a deterministic low-confidence nurture outcome with
`enrichment_status = not_found`, `scoring_status = skipped`, and
`reason = insufficient_firmographic_evidence`. Automated nurture email is
suppressed for this branch.

Gemini provider, safety, empty-candidate, missing-text, and JSON/schema errors
are classified and recorded as a `lead.scoring_failed` timeline event. Raw
provider error content is not persisted, and no score is fabricated.

## MQL, SQL, and PQL

- MQL at signup is based on verified identity plus ICP/firmographic fit.
- SQL requires the existing CRM/readiness or engagement evidence.
- PQL requires later AgentFlow product behavior and is owned by RevOps signal
  processing. A fresh signup is never PQL solely because of firmographics.
